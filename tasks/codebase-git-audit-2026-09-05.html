03 / Follow the user action

Where the promise breaks.

The most useful fixes preserve intent and state across time: selection, confirmation, background work and completion.

The prompt names A. The operation uses B.

Illustrated reproduction
Read P1-1 ↗
  1. Select backup A and start Restore. The prompt names A.
  2. Scroll the mouse wheel. The selected row changes to B.
  3. Press Yes. Execution reads the current selected row.

Observed in the audited checkout

The operation targets B even though the displayed confirmation names A.

Proposed acceptance boundary

Confirmation owns a frozen backup entry; later selection changes cannot redirect it.

P1-1Backup confirmation can restore or delete a different backupRecovery / ReproducedAddressed in source+

A confirmation must keep pointing to the backup you agreed to use.

Why it matters

Selecting backup A and then scrolling can make Yes operate on backup B.

Newer-branch evidence

Addressed in source at 890c446; the combined branch was not fully retested.

Proposed acceptance criteria

This is a development target, not a passed test or closure claim.

Source: internal/ui/screen_backups.go:174, :219, :253.

Select A, press Enter or d, scroll to B while the confirmation remains open, then press y. The prompt still names A, but execution reads the mutable backupIndex and uses B. Newer-branch evidence

P2-3Listing backups retains all backup contents in memoryRecovery / MeasuredCandidate work exists+

Seeing a list of backups should not load every backup into memory.

Why it matters

Larger backup collections consume memory proportional to all their contents before retention can prune them.

Newer-branch evidence

890c446 contains bounded-backup-catalog work. Candidate presence is not performance verification.

Proposed acceptance criteria

Measure retained heap while total backup bytes grow. Catalog listing must retain bounded metadata, with explicit budgets for any selected-content snapshot.

This is a development target, not a passed test or closure claim.
Read the audit evidence and source locations

Source: internal/backup/catalog.go:63, :83; internal/safefile/directory_unix.go:222.

Catalog creation snapshots every backup recursively, checks a second snapshot, and retains full payloads in returned authority objects. Restoring one backup or running retention first loads all backups. Four 4 MiB payloads retained 16,779,880 extra heap bytes after GC in the probe. Memory exhaustion is workload-dependent, but growth is unbounded and particularly problematic for Raspberry Pi users.

Action: bound catalog metadata and hashing, capture selected payloads on demand, and impose explicit budgets where content snapshots remain necessary. 890c446 is a bounded-backup-catalog candidate; review and test it rather than duplicating it.

07 / Interpretation & sources

Keep the conclusions precise.

Use the finding IDs to discuss scope. A smaller, well-defined fix is easier to review when its acceptance boundary is explicit.

Three backup risks, three boundaries

Wrong confirmation target, changed source contents and unbounded catalog memory are separate findings. Fixing the selected name does not prove source integrity or memory behavior.

A candidate is not a verified fix

Only the backup target correction was specifically marked addressed in newer source. Other relevant commits need review and combined testing; public delivery is a further step.

The APT deadlock is latent

The API reproduction blocks, but the current UI passes all=false. The audit corrected the older claim that this was a live dashboard Update All freeze.

Priority is not an exploit count

The five P1 findings include correctness and release blockers. No critical remote exploit was established; the standard-library advisory has a narrower applicability claim.

Other maintenance work worth keeping in view
  • Bound failure diagnostics. A doctor-repair test formatted full binary bytes into an approximately 193 MB log. An npm fixture can print inherited environment values on failure.
  • Use cohesive state boundaries. Large UI files are not defects by themselves. The reproduced bugs point toward shared async reducers, profile application and provider-preserving execution as useful extraction boundaries.
  • Validate manually edited enums. Some Manage values can become tmux/Lua syntax. No lower-trust route was established, so this remains hardening rather than a separate code-execution finding.
  • Support linked worktrees in tooling. The hook installer assumes .git is a directory; local lint/security hooks are only warnings. CI must be authoritative.
  • Reconcile documentation. Stale tool counts, sizes, historical testing notes and tracked backup lint configuration make the intended current product harder to identify.
